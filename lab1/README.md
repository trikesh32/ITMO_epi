## Задание

1. Сформировать функциональные требования к выданному веб-проекту.
2. Оценить трудоёмкость наивным методом.
3. Применить PERT, построить сетевую диаграмму, определить критический путь, предложить численность команды и срок разработки.
4. Оценить размер функциональными точками и трудоёмкость COCOMO II без локальной статистики.
5. Применить Use Case Points; для PF использовать собственный завершённый проект с известными трудозатратами.
6. Сравнить результаты и сделать выводы.

Для команды из трёх человек дополнительно нужен Planning Poker; здесь два автора.

## Результаты

| Метод | Трудоёмкость, чел·ч |
| --- | ---: |
| Наивный | 2 304 |
| PERT | 2 428 |
| FP + COCOMO II Early Design | 11 634,79 |
| UCP при **условном** PF = 20 | 4 556,80 |

Размер: **361 UFP**, **386,27 AFP**, **227,84 UCP**. COCOMO использует **UFP**, переводя его в 16,967 KSLOC по коэффициенту JavaScript 47 SLOC/FP.

Критический путь — **1 234,67 рабочих часа**, или **30,87 рабочей недели**. Выполнимое расписание для **3 разработчиков** достигает этой границы при полной доступности. При доступности 80% и отдельном резерве 15% плановый ориентир — **45 рабочих недель**. Человеко-часы трудоёмкости и срок проекта — разные величины.

**Ограничение пункта 5:** у авторов нет завершённого проекта с известными трудозатратами. Эмпирическая калибровка PF не выполнена. В отчёте приведены полный подсчёт UCP и сценарии PF = 10, 20, 30; чужой или вымышленный проект не выдаётся за собственный. Для полного выполнения этого подпункта потребуется реальный проект и его трудозатраты.

## Воспроизведение

Исходные требования, оценки и факторы: [scripts/data.py](scripts/data.py). Генератор: [scripts/build.py](scripts/build.py). Проверка согласованности: [scripts/verify.py](scripts/verify.py).

```sh
python3 -m venv /tmp/epi-lab-venv
/tmp/epi-lab-venv/bin/pip install -r scripts/requirements.txt
/tmp/epi-lab-venv/bin/python scripts/build.py
soffice -env:UserInstallation=file:///tmp/epi-lo-profile --headless --convert-to pdf --outdir docs docs/report.docx
/tmp/epi-lab-venv/bin/python scripts/verify.py
```

Генератор создаёт DOCX, Markdown, формульный Excel, draw.io, SVG/PDF/PNG сетевого графа и PNG расписания. Для PDF отчёта нужен LibreOffice. Для кириллицы используется Arial на macOS или DejaVu Sans на Linux. После изменения данных следует заново собрать весь комплект; изменения только в Excel не обновляют отчёт и рисунки. Сохранение формульной книги в Excel/LibreOffice обновляет кэш формул для программ просмотра.
